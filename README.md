# MEI攀 · 攀岩线路记录

按岩馆保存线路照片，设置 5.9、5.10a、5.10b 等难度，记录是否通关。支持手机和电脑浏览器。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev -- --port 5173 --strictPort
```

在本机访问 http://127.0.0.1:5173 。请固定使用这个地址，浏览器存储按地址隔离。

## 使用

1. 点击「添加线路」，选择已有岩馆或输入新岩馆名。
2. 设置默认难度，选择或拖入图片。每次最多 30 个文件；照片每张不超过 20 MB，视频一次 1 段。
3. 为每张图片填写名称、难度，并按需勾选「已经通关」，然后保存。
4. 在照片下方点击「待挑战 / 已通关」切换状态，点击照片可查看完整图片、编辑或删除线路。
5. 通过左侧岩馆、难度、状态和搜索组合筛选；难度按实际数字顺序排序。
6. 选择岩馆，点击标题旁的「重命名」，输入新名称并保存。原有线路、照片和通关状态保持不变；不能使用另一家已有岩馆的名称。
7. 打开网站或登录账号时，自动补齐公开名录中的 82 家上海场馆和分店，按名称或区名搜索。「补全上海岩馆」也可手动触发，重复执行不会重复添加，改过的名称会保留。恢复备份或导入本机记录时，默认馆名会接受备份中的自定义名称，已经手动改过的当前馆名优先保留。

上海名录整理于 2026-10-26，包含儿童馆和公园攀岩场地，并非全市完整名单，不保证实时营业状态。「名录与来源」可查看每家场馆的地址和资料链接。维护 `src/shanghai-gyms.json` 后运行 `node data/build-directory.mjs` 更新来源页面；场馆目录 ID 应保持稳定。

难度使用 YDS（美式）下拉选项：5.8、5.9，以及 5.10a–5.15d（每级包含 a/b/c/d）。批量上传可设置默认难度，也可逐张修改；旧记录中的其他难度在编辑时保留。HEIC / HEIF 支持取决于浏览器，无法读取时请先转为 JPG。照片会转为 JPEG，最长边最多 3200 像素（不放大小图），JPEG 编码质量为 0.94，透明背景变为白色。

右上角「森林 / 樱粉」可切换页面主题，当前浏览器自动记住选择；主题不影响照片、通关状态或云端数据。

## 视频压缩与播放

**原 Supabase 版：**支持 MP4 / MOV / WebM 视频输入；每段原文件不超过 1 GB（1024 MB）、最长 10 分钟、最高 4K。添加线路时默认「更省空间」（最长边 854px、最高 24fps、H.264 CRF 32、视频码率上限 600kbps、AAC 64kbps），也可选「标准」（最长边 1280px、最高 30fps、CRF 23、上限 2500kbps、AAC 128kbps）。保留原速、整段时长和声音，不裁剪；压缩后仍须不超过 20 MB。按时长动态降低视频码率，预留 10% 封装余量；10 分钟的视频会牺牲清晰度以适配保存上限。

先在设备浏览器里处理，预览显示前后大小，点击保存才上传。若重编码比原文件大且原文件是可兼容的 H.264/AAC MP4，会保留更小的原文件；其他格式可能为了兼容而增大，界面会明确显示。压缩比例不作固定保证。支持暂停、继续和取消（暂停需浏览器支持跨源隔离）；进度仅留在当前页面，刷新或关闭页面不可续接。切换账号时自动中止，不把待处理内容带给另一账号。视频用封面展示，打开详情后手动播放。

首次处理按需加载约 31 MB 的 FFmpeg WebAssembly（同站点托管）。支持跨源隔离的浏览器自动使用最多 4 个编码线程，低内存设备最多 2 个；多线程加载失败时回退到单线程。部署的 `_headers` 和开发服务器启用 COOP / COEP，以支持共享内存和真正暂停；不支持的浏览器隐藏暂停按钮，仍可取消。手机内存或性能不足可能失败，处理总耗时也可能比直接上传更长。整个处理过程累计运行最长 45 分钟，暂停时间不计入，失败或取消后释放 worker。加载依赖失败时可检查网络后重试。通过 WORKERFS 按需读取原文件，避免整份 1 GB 原视频复制进 WASM 内存；解码仍需内存，不能保证所有设备都能处理 1 GB / 4K 视频。输入原文件不会上传到第三方转码服务。

`npm run dev` / `npm run build` 会复制锁定的 FFmpeg 依赖到 `public/vendor/ffmpeg/` 和 `public/vendor/ffmpeg-mt/`；部署必须包含 `dist/_headers` 和整个 `dist/`，不要漏掉 wasm / worker 文件。已有云端项目使用 `supabase/enable-video.sql` 扩展 MIME 类型；本项目已通过控制台启用 `video/mp4`，仍为私有 bucket、20 MB 上限，RLS 未改动。包含视频的备份使用 v2 格式，仍可恢复旧 v1 照片备份，视频恢复不再二次压缩。

视频实际编码、原速播放、取消与重试、备份恢复和手机布局验证：`npm run test:video`（开发服务器须运行）。使用合成画面和测试音频，不处理用户真实媒体。

## 数据和备份

未登录时，照片与记录保存在当前浏览器的 IndexedDB，刷新后仍保留。清除网站数据、使用其他浏览器或更换网址，都可能导致本机记录不可见。建议定期点击「导出备份」。

登录后使用 Supabase 账号中的私有记录，每次成功修改自动保存到云端；另一台设备登录同一账号后读取云端，已打开的页面通过「刷新云端」获取新修改。首次登录不会自动上传本机数据，点击「导入本机记录」会合并岩馆和线路，同 ID 线路保留云端版本。退出账号后回到原来的本机记录，云端照片不会缓存到本机记录库。登录云端模式需要联网，写入失败会保留上一次成功保存的状态并提示重试；不同设备的旧版本不能覆盖新版本。

备份包含照片和线路信息。恢复备份采用合并方式，同一编号的已有线路保留当前版本，不重复导入。可通过备份文件手动迁移到另一台设备。一次恢复支持不超过 250 MB 的备份。

同一账号支持多设备记录；每次保存有版本检查，并发冲突需要先刷新后重试。没有多人共享线路或自动实时推送。

## Supabase 配置

本项目已连接 `xcndecoavcnohnmwsbhx`（首尔区域）。`src/cloud.js` 只包含公开项目 URL 和 publishable key，不能放入 secret/service-role key 或数据库密码。

- `supabase/setup.sql`：已在该项目执行一次，创建私有记录表、照片 bucket、按账号隔离的 RLS 策略。重复执行会因已存在对象而回滚，不要在同一项目再次执行。
- `supabase/verify-rls.sql`：在事务中验证账号隔离、版本冲突和匿名限制，最后回滚所有测试夹具，已通过。
- Email 注册、密码登录和邮箱验证已启用；当前 Site URL 为 `https://eloquent-cheesecake-e8cac9.netlify.app/`，Redirect URLs 保留 `http://127.0.0.1:5173/` 供本地开发。
- Supabase 默认 SMTP 仅向项目团队成员邮箱发送验证/重置邮件。面向其他用户开放前需要配置自有 SMTP，不能靠关闭邮箱验证解决。
- 更换正式域名时，同步修改 Authentication → URL Configuration 的 Site URL，并按需添加确切的 Redirect URLs。
- 图片上传完成后才提交记录；提交成功后尝试清理删除线路的图片。网络错误可能留下未引用图片，需要后续维护清理，不能直接按文件年龄删除仍被引用的图片。
- 当前实现每次读取完整个人收藏并下载照片与视频（同页面刷新复用已有照片），适用于个人规模；大量照片时需要进一步做分页和按需加载。

### 腾讯云版视频设置（2026-10-26）

`/tencent/` 原视频上限 1 GiB、20 分钟。可选「不压缩 · 原画质上传」，直接保留 MP4 / MOV / WebM 原片；仅用浏览器读取时长和封面，原片保存上限 1 GiB。压缩模式输出上限仍为 200 MiB。默认智能清晰：符合 MP4 品牌、H.264 yuv420p / AAC 的小于等于 200 MiB 文件不重新编码；符合相同编码要求的 MOV 优先无损转封装为 MP4；其余转为 720p（最长边 1280px）、CRF 23、最高 30fps、视频码率上限 2500kbps、AAC 128kbps，按时长适配 200 MiB 上限。可选 480p 省空间模式。大文件使用 WORKERFS 分片读取，视频最高仍支持 4K；处理耗时受设备性能影响。备份导入上限 512 MiB。云端调整见 `cloudbase/enable-original-video.sql`；回归测试 `npm run test:cloudbase-video`。

暂停与多核回归：`node tests/video-control.mjs`（5174），覆盖真实编码中的重复暂停/继续、暂停时取消、完整播放、MOV 无损转封装、多核加载失败回退、无跨源隔离兼容和手机布局。通过共享内存信号让忙碌的 WASM worker 在进度/日志回调处等待，继续后恢复同一任务；仅保留当前页面内的进度。
